# Payroll 급여 검증 및 마감 지원 시스템

> 전월·당월 급여자료 비교부터 이상변동 검토 및 마감까지

실무 Payroll 업무 프로세스(전월·당월 비교 → 검증 → 확인 필요 추출 → 담당자 검토 → 마감)를
반영한 **실무형 프로토타입**입니다. Employee Master(선택) + 전월/당월 Payroll(필수) Excel을
업로드하면 사번 기준으로 매칭·계산·비교·검증을 실제로 수행하며, 목업이 아니라 실제로 동작합니다.

## ⚠️ 이 프로그램의 성격

- 실제 대한민국 세법·4대보험 법정 요율을 사용하지 않습니다. `lib/payroll/rules.ts` 의 수치는
  전부 **"시연용 가상 계산 기준"**입니다.
- 검증 Rule(PAY-001~016)은 실제 Payroll 심사/감사 기준이 아니라 **"발표용 검증 예시 규칙"**입니다.
- 모든 임직원/금액 데이터는 **가상 데이터**입니다 (실제 인물·회사·계좌와 무관, 이메일은
  `@example.com` 도메인만 사용).
- AI는 급여 계산/비교/검증에 관여하지 않습니다. 전부 TypeScript의 결정론적(rule-based)
  로직이며, 최종 판단은 담당자가 검토 워크플로우를 통해 내립니다.
- 실제 회사 급여시스템/ERP 연동, 실제 세금·보험 신고, 로그인 기반 접근 제어는 포함하지
  않습니다. "마감" 은 실제 법적 승인 절차가 아니라 담당자의 검토완료 상태를 기록하는
  시연용 기능입니다.

## 기술 스택

- Next.js (App Router) + React + TypeScript
- Tailwind CSS
- SheetJS (xlsx) — 브라우저에서 실제 Excel 읽기/쓰기
- lucide-react — 아이콘
- 작업(run) 저장은 브라우저 **localStorage** 사용 (Storage Layer로 분리되어 있어 이후 실제
  DB/API로 교체 가능 — `lib/storage/runStorage.ts` 참고)

## 핵심 Workflow

```
기준월 선택
  → Employee Master(선택) + 전월 Payroll(필수) + 당월 Payroll(필수) 업로드
  → 검증 시작
  → 사번 매칭 (기존 / 신규 / 전월미존재)
  → 지급·공제 계산 (전월·당월 각각)
  → 전월 대비 비교
  → 검증 Rule 적용 (PAY-001~016)
  → 확인 필요 임직원 자동 추출
  → 검토함에서 직원별 상세(계산 근거) 확인 + 담당자 검토(메모/상태)
  → 마감
  → 결과 Excel 다운로드 (4개 시트)
```

## 로컬 실행

```bash
npm install
npm run dev
```

`http://localhost:3000` 접속 후 **샘플 데이터로 시작**을 누르면 바로 확인할 수 있습니다.

계산/검증/비교 엔진만 다시 확인하고 싶다면:


## 실제 업무 자료로 사용하는 방법

1. **Employee Master** (선택) — 컬럼: `사번, 성명, 부서, 직책, 재직상태` (필수),
   `이메일, 연락처, 입사일` (선택). 업로드하지 않아도 전월/당월 Payroll 만으로 핵심 기능은
   동작하며, 이 경우 부서/직책/이메일/연락처는 비어 있는 상태로 표시됩니다.
2. **전월 Payroll** / **당월 Payroll** (동일한 컬럼 구조, 당월은 필수) — 컬럼: `사번, 성명,
   재직상태, 기본급, 직책수당, 식대, 기타고정수당, 연장근로시간, 연장근로수당, 인센티브,
   성과급, 기타지급, 국민연금적용여부, 건강보험적용여부, 고용보험적용여부, 소득세,
   지방소득세, 기타공제`.
3. 파일들을 홈 화면의 각 업로드 영역에 넣고 **검증 시작**을 누릅니다.
4. 업로드 순서는 무관하며, 전월/당월 파일은 **사번을 기준으로 자동 매칭**됩니다 (이름이
   같다고 동일인으로 추정하지 않습니다).

Employee Master/Payroll 컬럼 헤더명이 위와 정확히 일치해야 인식됩니다. 정확한 형식은
홈 화면의 "sample_employee_master.xlsx / sample_payroll_previous.xlsx /
sample_payroll_current.xlsx 다운로드" 링크로 받은 파일을 참고하세요.

### 전월 Payroll 자동 이월

매달 전월 파일을 따로 찾아 업로드하지 않아도 되도록, **지난 작업의 당월 결과가 있으면
전월 Payroll 업로드가 선택사항으로 바뀌고** 홈 화면에 자동 이월 안내와 체크박스가 나타납니다.
체크되어 있으면 지난 작업에서 계산된 당월 결과(기본급/수당/보험적용여부 등 원본 입력값
기준)를 그대로 이번 달의 "전월" 입력으로 사용합니다. 전월 Payroll 파일을 직접 업로드하면
체크 여부와 무관하게 그 파일이 우선 사용됩니다. 이 시스템으로 지난달 작업을 저장해 둔
적이 없다면(최초 실행 등) 자동 이월 대상이 없으므로 평소대로 전월 파일 업로드가 필요합니다.

## 검증 Rule (발표용 검증 예시 규칙)

| Rule ID | 이름 | 심각도 |
|---|---|---|
| PAY-001 | 사번누락 | 오류 |
| PAY-002 | 사번중복 | 오류 (첫 번째 행 기준으로 처리) |
| PAY-003 | 성명누락 | 오류 |
| PAY-004 | 기본급누락/숫자오류 | 오류 |
| PAY-005 | 숫자형식 오류 (기본급 외) | 확인 필요 |
| PAY-006 | 지급항목 비정상 음수 | 기본급: 오류 / 그 외: 확인 필요 |
| PAY-007 | 보험 Y/N 오류 | 확인 필요 |
| PAY-008 | 연장근로시간>0 & 수당=0 | 확인 필요 |
| PAY-009 | 총지급 전월대비 기준초과 | 확인 필요 |
| PAY-010 | 기본급변경 | 확인 필요 |
| PAY-011 | 신규 지급항목 발생 | 확인 필요 |
| PAY-012 | 기존 지급항목 0원 전환 | 확인 필요 |
| PAY-013 | 보험적용 변경 | 확인 필요 |
| PAY-014 | 신규입사 | 정보 (집계에는 포함되지만 '오류/확인필요' 사유는 아님) |
| PAY-015 | 전월존재/당월미존재 | 확인 필요 (별도 보조 지표로도 표시) |
| PAY-016 | 퇴사자 지급항목 존재 | 확인 필요 |

한 직원에게 여러 Rule 이 동시에 적용될 수 있으며, '오류' 상태인 직원은 누락된 값을 임의로
추정하지 않고 0으로 처리한 채 검증 사유와 함께 그대로 표시합니다.

## 작업(run) 저장 - localStorage

- "검증 시작"을 누르는 즉시 하나의 작업(run)이 만들어져 브라우저 **localStorage**에
  저장됩니다 (원본 Excel 파일 자체는 저장하지 않고, 계산된 결과와 검토 상태만 저장합니다).
- 담당자가 검토상태/메모를 남기면 그 즉시 같은 작업에 반영되어 새로고침해도 유지됩니다.
- 홈 화면의 "최근 작업"(최근 3건 표시, 최대 20건 보관)에서 과거 작업을 다시 열어볼 수
  있습니다. 단, 과거 작업을 다시 열었을 때는 원본 업로드 자료가 세션에 없으므로 계산 기준
  재계산은 비활성화되며(검토상태/메모 수정은 계속 가능), 같은 세션에서 방금 계산한 작업만
  재계산할 수 있습니다.
- **실제 업무 적용 시 주의**: localStorage 는 같은 브라우저·같은 기기에서만 보이며, 접근
  권한 통제나 감사로그가 없습니다. 여러 담당자가 함께 쓰거나 사내 표준 절차로 운영하려면
  실제 DB/API 로 교체해야 하며, `lib/storage/runStorage.ts` 가 그 교체 지점입니다.

## 만들지 않은 것 / 실제 업무 적용 전 주의사항

- 실제 회사 급여시스템·ERP 연동, 실제 개인정보/고객사 데이터, 실제 세금·보험 신고는
  포함하지 않습니다.
- 로그인/회원가입, 접근권한 통제가 없습니다. 여러 담당자가 함께 쓰려면 이를 먼저
  추가해야 합니다.
- 검증 Rule/계산 요율은 시연용 예시이며, 실제 적용 전 회사 정책과 공식 Payroll 기준에
  따른 추가 검증이 필요합니다.
- localStorage 저장 구조는 시연 편의를 위한 것이며, 실제 운영에는 접근권한·보안·저장
  위치·파기 정책·감사로그에 대한 별도 검토가 필요합니다.
